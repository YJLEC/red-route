# 技术决策

## TD-001：静态 React 应用

- 状态：已采用
- 日期：2026-08-27
- 决策：使用 Vite、React 和 TypeScript，构建结果为纯静态文件。
- 原因：项目需要地图、景点联动、抽屉和响应式交互，但不需要账户、订单或其他后端能力。该方案能保持交互开发效率，同时符合 Cloudflare Pages 部署边界。
- 影响：目的地和路线必须由本地结构化数据驱动；任何外部地图或导航服务都只能是可替换增强，不能成为核心浏览的单点依赖。

## TD-002：可核验的关系地图优先

- 状态：已采用
- 日期：2026-08-27
- 决策：河北总览和景区内部导览优先采用仓库内的 SVG、GeoJSON 或路径数据；真实导航通过合规外链或可替换适配层提供。
- 原因：静态站不宜暴露不可控的地图密钥，也不能把核心体验绑定到调用额度、跨域限制或未经确认的第三方条款。
- 影响：研究阶段必须获得足够的位置和路线证据，地图不能凭空绘制。若官方资料不足，应记录精度限制。

实施结果：河北总览使用真实行政边界 GeoJSON；三地内部路线和抵达交通依据官方导览、具体交通页面与公开地理关系重绘，并在图内直接链接原始资料。高德地点或搜索页面作为无密钥外链提供，不复制未确认发布授权的官方导览图片，也不把核心浏览绑定到第三方地图脚本。

2026-08-28 补充：用户需要的是可用于出行判断的导览和交通信息，而不是装饰性示意图。因此重绘图必须包含真实节点、设施、路线方式与来源入口。若后续取得官方导览图的明确发布许可，或配置合规地图服务的密钥、额度与隐私说明，可以替换底层呈现；当前重绘方案不是能力限制，而是授权和静态部署边界下的发布选择。

## TD-003：正式图片缺失时使用自有占位状态

- 状态：已采用
- 日期：2026-08-27
- 决策：首版不发布尚未确认复用许可的官网图片，所有目的地和景点图片统一显示项目自有占位状态。
- 原因：现有材料没有图片，已找到的官网候选图未标注公开复用许可；宣传效果不能建立在不清楚的版权基础上。
- 影响：页面的信息结构、地图、路线和交通可视化完整可用，但视觉感染力仍会受缺图影响。获得授权图片后只需更新图片台账与数据配置，无需重写页面。
