# 产品与交互规格

## 产品任务

帮助游客完成五个连续决策：发现三个目的地、理解位置关系、比较游览条件、确定怎样抵达、确定到达后怎样游览。网站不承担实践活动汇报任务。

## 核心用户流程

### 流程 A：从地图选择目的地

1. 首屏看到河北轮廓和三个目的地标记；
2. 点击或键盘选择标记，右侧摘要立即切换；
3. 摘要给出主题、建议用时、游览强度和主要抵达方式；
4. 用户进入详情，查看内部路线和行前准备。

### 流程 B：比较后决定

1. 在首页切换到“比较”模式；
2. 按主题、空间类型、建议用时、强度、公共交通便利程度进行横向比较；
3. 选择最符合当前行程的目的地并进入详情。

### 流程 C：在详情页规划游览

1. 首屏看到内部路线示意和当前景点；
2. 点击地图点位或路线步骤，地图、路线和信息侧栏同步高亮；
3. 查看景点介绍、建议停留和前往方式；
4. 查看抵达方案、预约/开放核验和行前清单；
5. 通过官方页面或高德地图完成最终核验和导航。

## 信息架构

- `/`：河北总览地图、目的地摘要、三地比较；
- `/destination/hebei-museum`：城市博物馆室内展线；
- `/destination/xibaipo`：纪念馆与旧址群分层路线；
- `/destination/langya-mountain`：山地爬升路线；
- 404：返回河北总览。

## 交互规则

- 地图标记和路线点位使用真实 `button`，支持点击、Enter、Space 和清晰焦点样式；
- 当前选择不能只靠颜色表达，同时使用编号、文字和描边；
- 页面切换后标题更新并把焦点移动到主标题；
- 外部核验链接明确标注来源机构和核验日期；
- 不自动打开外部导航，不请求定位权限；
- 所有动效尊重 `prefers-reduced-motion`。

## 状态设计

- 地图加载：显示稳定尺寸的骨架轮廓，不改变整体布局；
- 地图失败：改用三个按地理顺序排列的目的地按钮，仍能完成选择；
- 图片缺失：显示项目自有的主题占位图和“图片待取得授权”；
- 图片加载失败：退回相同占位状态；
- 易变化信息：显示“核验于 YYYY-MM-DD”和“出发前再确认”；
- 来源冲突：不替用户选择一个看似确定的值，显示冲突提示和官网入口。

## 视觉方向

- 气质：克制、清晰、具历史重量，但首先是高频使用的旅游工具；
- 主色：纸白、墨黑、朱红；辅助使用松绿色和路线金色，避免单一红色页面；
- 地图与路线是第一视觉层级，标题不使用营销式超大字号；
- 卡片仅用于重复的目的地或景点条目，不把整个页面切成层层嵌套卡片；
- 圆角不超过 8px；命令按钮优先使用 Lucide 图标并提供可访问名称。
